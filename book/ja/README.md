# プログラミング言語 Emela

最初のプログラムからホストとの境界まで Emela を学べる入門書です。[`spec/`](../../spec/README.md) で仕様が定められている 0.20 系の言語について解説します。

本書は参考情報（非規範的）です。本書と仕様の記述が食い違う場合は仕様が正しく、本書の側を修正するものとします。

## 本書の構成

- **言語を 1 本の道筋で学びます。** 各章は前の章の内容を土台として順に積み上がっています。すでに一部の概念を知っている読者は、別の本を読む代わりに下記の読書ガイドを使って先に進めます。
- **言語の 2 つのレベルが最初の 2 部に対応します。** 第 I 部ではアプリケーションを書く人が使う機能を扱い、第 II 部ではライブラリやランタイム境界を書く人が使う機能を扱います（`[intro.layers]`）。第 I 部は第 II 部に依存しません。
- **エフェクトとハンドラが中心にあります。** リソース、構造化並行性、インターフェースを用いた設計、外部関数はいずれもハンドラから構築されるため、それらを定義する章の後に配置されています。

### 中断と並行性

多くの読者が抱いている待機と並行性のモデルは、他のどの要素よりも Emela のモデルと異なるため、付録 A のガイドではこれを独立して比較します。すべてのガイドの出発点となる事柄は次のとおりです。

- 非同期のための構文はありません。中断する可能性があることを示すのはエフェクト操作の宣言（`suspend fn`）だけで、関数シグネチャや呼び出しには何の印も付きません。関数が中断し得るかどうかは推論される `R` に表れます。
- 決めるのはハンドラです。同じ関数でも、後で再開するハンドラの下では中断し、その場で再開するハンドラの下では中断しません。後者の場合、`with` の型にも `Async` は現れません。ホストに渡すコールバックなど、中断しては困る場所では、型が `Immediate` を要求します。
- タスクは 1 つのスレッド上で協調的に切り替わるファイバ上で動き、切り替わるのは中断し得る呼び出し箇所のみです。ランタイムは公平性のために、経過時間ではなくその種の呼び出し回数に応じて制御を譲るため、譲る箇所は毎回同じになります。中断し得る呼び出しを含まない区間は 1 ステップとして実行されます。並列実行（パラレリズム）はなく、スレッドもロックもありません。
- タスクは `Task.Group` または `Task.Background` の中でのみ開始でき、開始した `with` が終わる前に終了します。単一のタスクに割り込む関数はありません。
- 継続の再開は最大 1 回までです。

| 知っている言語・環境 | そこで使うもの | Emela で注目すべき点 |
|---|---|---|
| Java | スレッド、仮想スレッド、Executor、ロック | シングルスレッドでロックなし、`with` で寿命が限定されるタスク |
| Haskell | `IO`、`forkIO`、`async`、STM | モナドではなくエフェクト操作としての待機、トランザクションの代わりに中断点間のアトミックな区間 |
| Rust | `async fn`、`.await`、Future、Executor、`Send` | 関数の色分け（coloring）なし、ランタイムはプログラムの一部、スレッド間共有なし |
| Gleam | BEAM 上のプロセスとメッセージ | メールボックスを持つプロセスではなく、結果を join するタスク |
| ZIO, Effect-TS | ファイバ、`fork`、割り込み、スコープ、`Deferred`・`Semaphore`・`Queue` | 同じ道具立てをダイレクトスタイルで。グループ外の `fork` なし、単一ファイバへの割り込み関数なし |

## 本書の執筆方針

- 各章は Emela 自身の言葉でルールを述べます。他言語との比較は各章ではなく付録 A にまとめます。
- 章がルールに依拠する箇所には仕様のセクション名（`[effect.handler]`）を記載し、読者が正確な文言を参照できるようにします。
- コード例は `emela fmt` の出力に一致させ、現在のコンパイラでコンパイルできることを確認しています。特記がない限り、記載する出力は JS ターゲットでの `emela run` の出力です。
- 現在の実装と言語仕様は切り分けて記述します。現在のコンパイラの挙動について述べる文はその旨を明記します。
