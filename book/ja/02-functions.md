# 2. 関数と式

第 1 章ではデータを定義しました。この章ではそれを扱う関数を書きます。関数の宣言と呼び出し方、束縛と式による関数本体の組み立て方、そして `if` と `match` によって何を計算するかを選ぶ方法を扱います。

関数本体の中にあるものはすべて式であり、値を持ちます。ブロックも、`if` も、`match` も式です。式でない唯一の要素は、値に名前を付ける束縛です。

## 関数を宣言する

```emel
fn add(x: Int, y: Int) -> Int {
  x + y
}

fn main() {
  dbg(add(1, 2))
  ()
}
```

```console
$ emela run
3
```

宣言は `fn` で始まり、関数名、型付きのパラメータ、そして `->` の後に戻り値の型が続きます。本体はブロックで、その最後の式の値が関数の結果になります。`return` はありません。関数は本体の末尾に到達して終了します。

パラメータの型は必ず書きます。戻り値の型は省略でき、その場合はコンパイラが本体から推論します。

```emel
fn double(n: Int) {
  n * 2
}
```

`double` は `Int` を返し、別の型を期待する呼び出し側はコンパイルエラーになります。推論された型はエディタ上に表示されます（第 18 章）。他のモジュールから使われる関数は、何を返すかシグネチャから分かるように戻り値の型を書くのが一般的です（第 7 章）。

宣言には、その関数がどのエラーで失敗し得るか（`fails`、第 5 章）や、どのエフェクトを使うか（`uses`、第 6 章）も書けます。`uses` を省略した場合、エフェクトは常に推論されます。エラーは戻り値の型と両方とも省略したときに一緒に推論されます。戻り値の型を書いて `fails` を書かない関数は「失敗しない」と宣言したことになり、コンパイラはそれを強制します。

### 引数とその名前

パラメータの名前は、呼び出し時の引数の名前にもなります。引数は位置指定、名前指定、または先頭を位置指定にして残りを名前指定で渡せます。

```emel
fn connect(host: String, port: Int) -> String {
  "#{host}:#{port}"
}

fn main() {
  dbg(connect("localhost", 5432))
  dbg(connect("localhost", port: 5432))
  dbg(connect(host: "localhost", port: 5432))
  port = 8080
  dbg(connect("example.com", port:))
  ()
}
```

```console
$ emela run
"localhost:5432"
"localhost:5432"
"localhost:5432"
"example.com:8080"
```

- 位置引数を先に書きます。`connect(host: "localhost", 5432)` はコンパイルできません。
- 変数がパラメータと同じ名前のとき、`port:` だけは `port: port` の省略形になります。
- `resize(img, width: 640, height: 480)` のように値だけでは意味が分かりにくい箇所では、引数を名前付きにすると呼び出しが読みやすくなります。
- 呼び出し側が名前を書けるため、パラメータ名も関数が提供する約束の一部です。公開関数のパラメータ名を変更すると呼び出し側が壊れることがあります。

コンストラクタも同じルールに従うため（第 1 章）、`User(1, name: "Ada")` も通常の呼び出しと同じです。

### 型パラメータ

関数名の後に `[ ]` で型パラメータを書くと、任意の型の値に対して動作する関数を作れます。

```emel
fn first[A](xs: List[A]) -> Option[A] {
  xs match {
    [x, ..] -> Some(x)
    []      -> None
  }
}

fn main() {
  dbg(first([3, 1, 2]))
  dbg(first(["a"]))
  ()
}
```

```console
$ emela run
Some(3)
Some("a")
```

呼び出し時に型引数は書きません。引数から自動的に決まります。`first([3, 1, 2])` は `A` を `Int` として `first` を呼び出します。`first` の本体は `A` が何の型か知らないため、`A` の値を保持したり別の値に入れたりそのまま渡したりすることしかできず、比較や表示はできません。`[A: Show]` のような境界を使ってさらに多くの操作を可能にする方法は第 9 章で説明します。

## ブロックと束縛

束縛は `name = expression` と書きます。前にキーワードは付きません。

```emel
fn main() {
  count = 1
  count = count + 1
  dbg(count)
  (q, r) = (17 / 5, 17 % 5)
  dbg(q)
  dbg(r)
  total: Int64 = 1
  dbg(total)
  ()
}
```

```console
$ emela run
2
3
2
1
```

- 変数は決して変化しません。`count = count + 1` は `count` という新しい束縛を作り、その行以降はその名前が新しい値を指します。すでに古い値を使っていたコードは古い値を保持し続けます。代入はありません。
- 左辺には、必ずマッチするパターンであれば任意のパターンを書けます。`(q, r)` はペアを分解します。`Some(x)` のようにマッチに失敗する可能性があるパターンは、失敗したときに束縛する値がないため束縛の左辺には書けずコンパイルエラーになります。そのような場合は `match` を使います。
- `total: Int64 = 1` のように名前の後に型を書けます。これが必要になるのは、そのままでは `Int` になるリテラル `1` のように、値だけでは型が決まらない場合だけです。

ブロック `{ ... }` もまた式です。ブロック内の束縛はその内側でのみ可視であり、ブロックの値は最後の式の値になります。

```emel
fn main() {
  area = {
    width = 3
    height = 4
    width * height
  }
  dbg(area)
  ()
}
```

```console
$ emela run
12
```

改行が文の終わりを表すため、セミコロンはありません。`(` や `[` が開いている間、または次の行が `+` や `&&` のような二項演算子、`.`、あるいは `else` で始まるとき、式は次の行へ継続します（`[lex.continuation]`）。行末に演算子があっても継続しません。行頭の `-` と `||` は代わりに新しい文を開始するため、複数行にまたがる減算や `||` は括弧の中に書きます。

## 演算子

| 演算子 | 種類 |
|---|---|
| `!x` `-x` | 否定・単項マイナス |
| `*` `/` `%` | 乗算、除算、剰余 |
| `+` `-` | 加算、減算 |
| `==` `!=` `<` `<=` `>` `>=` | 比較 |
| `&&` | 論理積（AND） |
| `\|\|` | 論理和（OR） |

表の上にある演算子ほど強く結合します。`!a && b` は `(!a) && b` であり、`1 + 2 * 3` は `7` です（`[fn.operator]`）。パイプと `match` はこれらすべてより弱く結合します（第 3 章）。最初から知っておくべきルールがいくつかあります。

- 算術演算は `Int`、`Int64`、`Float` に対して動作し、両辺は同じ型でなければなりません。`1 + 2.0` はコンパイルできないため、`1.0 + 2.0` と書くか、関数で片方を変換します。
- `+` は文字列を連結しません。文字列補間 `"#{a}#{b}"` を使います。
- `==` と `!=` は `Eq` を持つ型で使えます。`<`、`<=`、`>`、`>=` は `Ord` を持つ型（第 1 章）に加えて、`Ord` を持たない `Float` にも直接使えます（第 9 章）。
- 比較は連鎖できません。`0 < a < 3` はコンパイルできないため、`0 < a && a < 3` と書きます。
- `&&` と `||` は、左辺だけで結果が決まらないときにのみ右辺を評価します。
- 自分で宣言した型に独自の演算子を定義することはできません。`Money.add(a, b)` のように関数を書きます。
- ビット演算子はありません。代わりに `Int.bit_and(a, b)` や `Int.shift_left(a, 2)` のような関数を使います。

## if

`if` は 2 つのブロックのいずれかを選び、選んだブロックの値が式全体の値になります。条件は `Bool` であり、括弧は不要です。

```emel
fn describe(n: Int) -> String {
  sign = if n < 0 { "negative" } else if n == 0 { "zero" } else { "positive" }
  parity = if n % 2 == 0 { "even" } else { "odd" }
  "#{n} is #{sign} and #{parity}"
}

fn main() {
  dbg(describe(-3))
  dbg(describe(10))
  ()
}
```

```console
$ emela run
"-3 is negative and odd"
"10 is positive and even"
```

`else` のない `if` の値は `()` になるため、値を返すためではなく何らかの作用を行うブロックにのみ使います。`x = if ready { 1 }` は `ready` が `False` のときに値がないためコンパイルできません。`if` 自体が値を持つため、独立した条件演算子（三項演算子）はありません。

## match

`match` は値をその形によって分解します。値の後ろに続けて書きます。

```emel
enum Shape {
  Circle(radius: Float)
  Rect(Float, Float)
  Empty
}

fn area(shape: Shape) -> Float {
  shape match {
    Circle(radius:) if radius > 0.0 -> 3.14 * radius * radius
    Circle(_)                       -> 0.0
    Rect(w, h)                      -> w * h
    Empty                           -> 0.0
  }
}

fn main() {
  dbg(area(Circle(radius: -1.0)))
  ()
}
```

```console
$ emela run
0.0
```

アームは上から順に試され、最初にパターンがマッチしたアームが `match` の値になります。アームにはパターンの後に `if condition` という*ガード*を付けられます。そのアームが選ばれるのは、パターンがマッチし、かつ条件が `True` のときだけです。パターンで束縛した名前は、そのガードや `->` の右辺で使えます。

値を先に書くのは、コードを実行される順序で左から右へ読めるようにするためです。これは値自体が呼び出しの連鎖のような長い式になるときに特に効いてきます（第 3 章）。`match value { ... }` のように `match` を先に書くとコンパイルエラーになります。

### パターン

| パターン | マッチするもの |
|---|---|
| `_` | 何にでもマッチし、束縛しない |
| `x` | 何にでもマッチし、`x` に束縛する |
| `0`、`-1`、`"yes"` | リテラルに等しい値 |
| `MAX_SIZE` | 定数に等しい値 |
| `Empty`、`Rect(w, h)`、`Circle(radius: r)`、`Circle(radius:)` | そのコンストラクタで作られた値（各フィールドにパターンを指定） |
| `User(name:, ..)` | コンストラクタの値（書いていないフィールドは無視） |
| `(a, b)` | タプル（要素ごとにマッチ） |
| `[]`、`[x]`、`[x, y]`、`[x, ..rest]`、`[x, ..]` | 空リスト、ちょうど 1 要素または 2 要素のリスト、先頭要素と残りのリスト |

パターンはネストできます。`Some(Some(n))` は数値を保持する `Option[Option[Int]]` にマッチし、`(0, _)` は第 1 要素が `0` のペアにマッチします。名前付きフィールドを持つコンストラクタのパターンでは、すべてのフィールドを書くか、残りを気にしないことを示す `..` を末尾に置きます。`..` なしでフィールドを省略するとコンパイルエラーになります。

```emel
type User(id: Int, name: String, admin: Bool)

fn greeting(user: User) -> String {
  user match {
    User(admin: True, name:, ..) -> "Welcome back, administrator #{name}"
    User(name:, ..)              -> "Hello, #{name}"
  }
}

fn fizzbuzz(n: Int) -> String {
  (n % 3, n % 5) match {
    (0, 0) -> "FizzBuzz"
    (0, _) -> "Fizz"
    (_, 0) -> "Buzz"
    _      -> Int.to_string(n)
  }
}

fn summary(xs: List[Int]) -> String {
  xs match {
    []          -> "empty"
    [x]         -> "just #{x}"
    [x, y]      -> "#{x} and #{y}"
    [x, ..rest] -> "#{x} and #{List.length(rest)} more"
  }
}

fn main() {
  dbg(greeting(User(id: 1, name: "Ada", admin: True)))
  dbg(greeting(User(id: 2, name: "Bob", admin: False)))
  dbg(fizzbuzz(9))
  dbg(fizzbuzz(15))
  dbg(summary([1]))
  dbg(summary([1, 2, 3, 4]))
  ()
}
```

```console
$ emela run
"Welcome back, administrator Ada"
"Hello, Bob"
"Fizz"
"FizzBuzz"
"just 1"
"1 and 3 more"
```

`fizzbuzz` は 2 つの値で同時に分岐するため、その場でタプルを作ってマッチしています。

### すべてのケースを処理する

取り得るすべての値を網羅していない `match` はコンパイルできず、エラーメッセージには漏れている値の例が表示されます。

```console
$ emela check
error[E3102]: non-exhaustive match: pattern `Circle(_)` not covered
   ╭─[ src/main.emel:8:3 ]
   │
 8 │   shape match {
   │   ──┬──
   │     ╰────
───╯

1 error
```

これは先ほどの `area` から `Circle(_)` のアームを取り除いたときのメッセージです。`emela check` はプログラムをビルド・実行せずにエラーを報告します。ガード付きのアームは条件が `False` になる可能性があるためパターンを網羅したものとはみなされません。そのため `area` には 2 つ目の `Circle` アームが必要です。

検査は逆方向にも働きます。上のアームがすでにすべてのケースにマッチしているため決して選ばれないアームには警告（W3101）が出ます。

## まとめ

- 関数はパラメータの型を宣言します。戻り値の型とエフェクトは省略すれば推論され、戻り値の型を省略していればエラーも一緒に推論されます。
- ブロックの最後の式がその値になります。`return` もセミコロンもありません。
- 引数は位置指定を先に、名前指定を後に書きます。パラメータ名は関数のインターフェースの一部です。
- 変数は決して変化しません。同じ名前を再び束縛すると新しい束縛になります。
- `if` と `match` は式です。`match` は値の後ろに書き、アームを上から順に試し、すべてのケースを処理しなければなりません。

第 3 章では関数を値として扱います。他の関数へ渡す方法、インラインで書く方法、そしてパイプで呼び出しをつなぐ方法を学びます。
