# 1. データ

Emela のプログラムはデータから始まります。まず解決したい問題に現れる値がどのようなものかを表現し、それからその値を分解して新しい値を組み立てる関数を書きます。この章では前半部分、つまりデータの定義方法を扱います。

データの定義方法は 3 つあります。

- `type` はフィールドを持ちます。たとえばユーザーは ID と名前を持ちます。
- `enum` はケースを持ちます。たとえば図形は円、長方形、または空のいずれかです。
- タプルは名前を付けずにいくつかの値をまとめます。たとえば `(1, "one")` のように書きます。

値は決して変化しません。値を「変更する」には、元の値から新しい値を作ります。

## 例を実行する

プロジェクトを作成して実行してみましょう。

```console
$ emela new hello
created application `hello`
$ cd hello
$ emela run
Hello, world!
```

プロジェクトは `Pome.toml` と `src/` 以下のソースコードからなるディレクトリです。プログラムは `src/main.emel` の `main` から始まります。この章の例を試すときは、`src/main.emel` の中身をその例で置き換えてください。

`emela run` は最初にプログラムを実行するコマンド（`running` で始まる行）を標準エラーに出力します。本書の出力例ではその行を省略しています。

`emela new` が生成するプログラムは `Console` エフェクトを使って出力していますが、これについては第 6 章で説明します。それまでの例では `dbg` を使います。`dbg` は値を構築するのと同じ形式で標準エラーに出力し、その値をそのまま返します。

```emel
fn main() {
  dbg(1 + 2)
  ()
}
```

```console
$ emela run
3
```

`dbg` はデバッグ用途のためのものであり、関数の型に含まれない唯一の出力手段です。それ以外の出力はすべて副作用であり、Emela では副作用が関数の型の一部になるため、ちゃんとした出力方法は第 6 章まで待ちます。

関数本体の最後の式の値が、その関数の結果になります。`dbg` は引数をそのまま返すため、`dbg(1 + 2)` で終わる `main` は `3` を返すことになり、コンパイラはその値が捨てられることを警告します。末尾に `()` を置くことで、結果を何も情報を持たない値である Unit にしています。

## 基本型

| 型 | 値 |
|---|---|
| `Int` | 32 ビット符号付き整数：`42`、`1_000_000`、`0xFF`、`0b1010` |
| `Int64` | 64 ビット符号付き整数 |
| `Float` | 64 ビット浮動小数点数：`3.14`、`1.0e9` |
| `Bool` | `True` と `False` |
| `String` | テキスト：`"hello"`、複数行テキスト用の `"""` |
| `()` | Unit。唯一の値は `()` |
| `Never` | 値をまったく持たない型。第 5 章で登場します |

早い段階で知っておくべきルールがいくつかあります。

- 整数リテラルは、書かれた場所が `Int64` を要求する場合を除き `Int` です。`Float` になることは決してありません。`Float` が必要な場所では `2` ではなく `2.0` と書きます。
- 数値型どうしの暗黙の変換はありません。`Int64.from_int(n)` で `Int` を `Int64` に、`Float.round(x)` で `Float` を `Int` に変換します。
- 整数演算はオーバーフロー時に折り返します（ラップアラウンド）。`2147483647 + 1` は `-2147483648` です。整数を 0 で割るとプログラムは停止します（*欠陥*、第 5 章）。
- `True` と `False` はキーワードではありません。これらは `Bool` の 2 つのコンストラクタであり、他のすべてのコンストラクタと同じく大文字で始まります。
- 文字型（char）はありません。1 文字は長さ 1 の `String` です。

文字列の中には `#{...}` で他の値を埋め込めます。

```emel
fn main() {
  name = "Ada"
  dbg("Hello, #{name}! 1 + 2 = #{1 + 2}")
  ()
}
```

```console
$ emela run
"Hello, Ada! 1 + 2 = 3"
```

`name = "Ada"` は `name` という名前を値に束縛します。束縛のためのキーワードはなく、代入もありません。同じ名前をもう一度束縛すると新しい束縛が作られ、古い方の値は変わりません。束縛の詳細は第 2 章で扱います。

## フィールドを持つ型

`type` 宣言はフィールドの集まりに名前を付けます。

```emel
type User(id: Int, name: String)
```

これは `User` 型と同名のコンストラクタを宣言します。値はコンストラクタを呼び出して作り、フィールドは `.` で読み取ります。

```emel
type User(id: Int, name: String)

fn main() {
  ada = User(id: 1, name: "Ada")
  dbg(ada.name)
  dbg(ada)
  ()
}
```

```console
$ emela run
"Ada"
User(id: 1, name: "Ada")
```

コンストラクタの引数は通常の関数の引数と同じルールに従います（`[fn.args]`）。位置指定、名前指定、または先頭を位置指定にして残りを名前指定で渡せます。`User(1, "Ada")`、`User(1, name: "Ada")`、`User(id: 1, name: "Ada")` はすべて同じ値を作ります。変数がフィールドと同じ名前の場合、`User(id:, name:)` は `User(id: id, name: name)` の省略形になります。

型は名前によって区別されます。同じフィールドを持っていても名前が異なる 2 つの型は別の型であり、`id` と `name` を持つ別の型が期待される場所に `User` を渡すことはできません。名前のないレコード型はありません。

### 一部のフィールドを差し替える

値は変化しませんが、元の値から一部のフィールドだけを差し替えた新しい値を作れます。差し替えたいフィールドを書き、その後に `..` と残りのフィールドを引き継ぐ値を続けます。

```emel
type User(id: Int, name: String)

fn main() {
  ada = User(id: 1, name: "Ada")
  grace = User(name: "Grace", ..ada)
  dbg(grace)
  dbg(ada)
  ()
}
```

```console
$ emela run
User(id: 1, name: "Grace")
User(id: 1, name: "Ada")
```

`ada` から `grace` を作った後も、`ada` は元のままです。

## Enum

`enum` は値が取り得るケースをすべて列挙します。各ケースを*バリアント*と呼びます。

```emel
enum Shape {
  Circle(radius: Float)
  Rect(Float, Float)
  Empty
}
```

バリアントは、名前付きフィールド（`Circle`）、位置フィールド（`Rect`）、またはフィールドなし（`Empty`）のいずれかを持ちます。1 つの enum の中でこれら 3 種類を混在させることはできますが、1 つのバリアントの中で名前付きフィールドと位置フィールドを混ぜることはできません。バリアントは 1 行に 1 つ書くか、カンマで区切って書きます。

バリアントはその enum のコンストラクタであり、それ自体が独立した型ではありません。`Circle(radius: 1.0)` は `Shape` 型であり、円だけを受け取る関数を宣言することはできません。同じ理由で、バリアントのフィールドを `.` で読み取ることもできません。`Shape` は `Circle` ではないかもしれないからです。中身を見るには `match` を使います。

```emel
enum Shape {
  Circle(radius: Float)
  Rect(Float, Float)
  Empty
}

fn area(shape: Shape) -> Float {
  shape match {
    Circle(radius:)     -> 3.14 * radius * radius
    Rect(width, height) -> width * height
    Empty               -> 0.0
  }
}

fn main() {
  dbg(area(Circle(radius: 1.0)))
  dbg(area(Rect(2.0, 3.0)))
  ()
}
```

```console
$ emela run
3.14
6.0
```

`match` の各アームは、`->` の左にパターン、右にそのケースの結果を持ちます。パターンは値を作るときのコンストラクタ呼び出しと同じ形をしており、その中の名前がフィールドを束縛します。`Circle(radius:)` は `radius` を束縛し、`Rect(width, height)` は 2 つの位置フィールドを束縛します。`match` とパターンの詳細は第 2 章で扱います。

enum は閉じています。宣言の外側からバリアントを追加することはできません。だからこそ、コンパイラは `match` がすべてのケースを処理しているかを検査できます。ケースを 1 つでも漏らした `match` はコンパイルエラーになるため、`Shape` にバリアントを追加すると、それを処理しなければならないすべての `match` がコンパイラによって指摘されます。

## タプル

タプルは 2 つ以上の値を位置によってまとめます。型も値と同じ形で書きます。

```emel
fn main() {
  pair: (Int, String) = (1, "one")
  (number, word) = pair
  dbg(number)
  dbg(word)
  ()
}
```

```console
$ emela run
1
"one"
```

`(number, word) = pair` でタプルを分解しています。タプルパターンのように必ずマッチするパターンであれば、束縛の左辺に書くことができます。

要素が 1 つだけのタプルはありません。`(x)` は括弧で囲んだ `x` です。要素が 0 個のタプルは `()` であり、基本型の表にあった Unit 値です。タプルの各要素に名前を付けた方がよい場面では、`type` を使うのが適切です。

## 型パラメータ

型は `[ ]` の中に型パラメータを書くことで、一部のフィールドの型を開いたままにできます。

```emel
type Pair[A, B](first: A, second: B)

fn main() {
  p = Pair(first: 1, second: "one")
  dbg(p)
  q = Pair(first: "uno", ..p)
  dbg(q)
  ()
}
```

```console
$ emela run
Pair(first: 1, second: "one")
Pair(first: "uno", second: "one")
```

型引数は値から決まります。`p` は `Pair[Int, String]` であり、`first` を `String` に差し替えた `q` は `Pair[String, String]` です。

型パラメータを持つ 2 つの型が、インポートなしでどこからでも使えます。

- `Option[A]` は `Some(value)` または `None` のいずれかです。Emela には null がありません。値が存在しない可能性がある場合は `Option` 型を使い、その値を使うコードは `None` を処理しなければなりません。
- `List[A]` は同じ型の値を並べたリストで、`[1, 2, 3]` のように書きます。

リストにインデックスアクセスするための構文はありません。`List.get(xs, 0)` はリストの長さが足りない可能性があるため、`Option` を返します。

```emel
fn main() {
  xs = [10, 20, 30]
  dbg(List.get(xs, 0))
  dbg(List.get(xs, 5))
  ()
}
```

```console
$ emela run
Some(10)
None
```

`List.get` は先頭にモジュール名を付けて呼び出します。常に可視であるいくつかの名前（`[lib.prelude]`）を除き、標準ライブラリの関数はこのように呼び出します。

## 定数

`const` はモジュールのトップレベルで値に名前を付けます。名前は大文字で書きます。

```emel
type Config(port: Int, host: String)

const DEFAULT_PORT = 8080

const DEFAULT_CONFIG = Config(port: DEFAULT_PORT, host: "localhost")

fn main() {
  dbg(DEFAULT_CONFIG)
  ()
}
```

```console
$ emela run
Config(port: 8080, host: "localhost")
```

右辺では関数を呼び出せますが、エフェクトを使うことや `fail` することはできません（`[data.const]`）。定数は最初に使用されたときに評価されます。

## 値の比較と表示

`==` は 2 つの値を比較し、文字列中の `#{...}` は値を表示します。しかし自分で宣言した型では、明示的に指定するまでどちらも使えません。等価性や表示の意味はその型に関する設計上の判断だからです。最も簡単な指定方法は `derive` を使うことで、フィールドの構成からコンパイラにコードを生成させます。

```emel
type Point(x: Float, y: Float)
  derive Eq, Show

enum Direction {
  North
  East
  South
  West
}
  derive Eq, Ord

fn main() {
  p = Point(x: 1.0, y: 2.0)
  dbg(p == Point(1.0, 2.0))
  dbg("p is #{p}")
  dbg(North < South)
  ()
}
```

```console
$ emela run
True
"p is Point(x: 1.0, y: 2.0)"
True
```

- `Eq` は `==` と `!=` を提供します。自動導出された `Eq` は各フィールドを比較します。
- `Ord` は `<`、`<=`、`>`、`>=` を提供します。自動導出された `Ord` はバリアントを宣言された順に並べ、フィールドを先頭から順に比較します。`Eq` も必要です。
- `Show` は `#{...}` での表示を提供します。自動導出された `Show` は値を構築する形式の文字列を出力します。

`derive Eq` がなければ `p == Point(1.0, 2.0)` はコンパイルできず、`derive Show` がなければ `"p is #{p}"` もコンパイルできません。あらゆる型の値を表示できるのは `dbg` だけであり、先ほどの例で何も derive していない型に対して `dbg` が使えたのはそのためです。

`Int`、`Int64`、`String`、`Bool` はこれら 3 つすべてを持ちます。`Float` は `Eq` と `Show` を持ちますが `Ord` を持たないため、`Float` フィールドを持つ型は `Ord` を derive できません。タプル、`List`、`Option` はそれぞれの要素型が持っている場合にそれらを持ちます。これらの名前はトレイトです。トレイトとは何か、また手動でどう書くかについては第 9 章で説明します。

## まとめ

- `type` はフィールドを持ち、`enum` はケースを持ち、タプルは値を位置でまとめます。これら 3 つはすべて同じ `( )` の形で構築・分解します。
- 値は変化しません。`Type(field: value, ..old)` で古い値から新しい値を作ります。
- バリアントはコンストラクタであり、型ではありません。中身はすべてのケースを処理する `match` で読み取ります。
- 欠損する可能性のある値は null ではなく `Option` で表します。リストにインデックス構文はありません。
- 等価性・順序・表示は `derive Eq, Ord, Show` で型に付与します。

第 2 章では、これらのデータを扱う関数を書いていきます。
