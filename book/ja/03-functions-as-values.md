# 3. 値としての関数

関数は数値やリストと同じく 1 つの値です。別の関数に渡したり、関数から返したり、束縛に格納したりできます。この章では関数を値として書く方法、その型の表し方、そして連続する処理を読みやすく保つ 2 つの呼び出し方法（パイプとメソッド呼び出し）を紹介します。

## 関数を渡す

`List.map` はリストの各要素に関数を適用し、`List.filter` は関数が `True` を返す要素だけを残します。関数は他の引数とまったく同じように渡せます。

```emel
fn double(n: Int) -> Int {
  n * 2
}

fn is_even(n: Int) -> Bool {
  n % 2 == 0
}

fn main() {
  xs = [1, 2, 3, 4]
  dbg(List.map(xs, double))
  dbg(List.filter(xs, is_even))
  dbg(List.map(xs, Some))
  ()
}
```

```console
$ emela run
[2, 4, 6, 8]
[2, 4]
[Some(1), Some(2), Some(3), Some(4)]
```

関数名を呼び出さずにそのまま書くと、その関数が値として得られます。フィールドを持つコンストラクタも関数です。`Some` は値を 1 つ受け取り `Option` を返します。

## 無名関数

1 か所でしか使わない関数に名前を付ける必要はありません。無名関数はパラメータを `|` と `|` の間に並べ、その後に本体を書きます。

```emel
fn main() {
  xs = [1, 2, 3, 4]
  dbg(List.map(xs, |n| n * 10))
  dbg(List.fold(xs, from: 0, f: |sum, n| sum + n))
  lines = List.map(xs, |n| {
    squared = n * n
    "#{n}^2 = #{squared}"
  })
  dbg(lines)
  scores = [("Ada", 90), ("Bob", 72)]
  dbg(List.map(scores, |(name, score)| "#{name}: #{score}"))
  greet = || "hello"
  dbg(greet())
  ()
}
```

```console
$ emela run
[10, 20, 30, 40]
10
["1^2 = 1", "2^2 = 4", "3^2 = 9", "4^2 = 16"]
["Ada: 90", "Bob: 72"]
"hello"
```

- パラメータはカンマで区切ります（`|sum, n| sum + n`）。`List.fold` は `from` から始めて要素を 1 つずつ結合します。第 4 章ではこれを繰り返しに使います。
- 本体は 1 つの式であり、右に伸ばせる限り伸びます。複数の文を書くときは本体をブロックにします（`|n| { ... }`）。
- パラメータには必ずマッチするパターンを書けます。`|(name, score)|` はペアを分解しています。
- パラメータのない関数は `||` で書きます。
- パラメータの型は通常省略します。型は関数を渡す場所から決まります。`List.map(xs, |n| n * 10)` では、`xs` が `Int` のリストなので `n` は `Int` になります。他から決まらない場合は `|n: Int| n + 1` のように明記できます。

本体は右側のすべてを取り込むため、無名関数をその場で呼び出すときは括弧で囲みます。`(|x| x + 1)(2)` は `3` です。

## 関数型

関数を受け取るパラメータは関数型を持ち、`fn(パラメータ型) -> 戻り値型` のように書きます。

```emel
fn apply_twice(f: fn(Int) -> Int, x: Int) -> Int {
  f(f(x))
}

fn adder(n: Int) -> fn(Int) -> Int {
  |x| x + n
}

fn main() {
  dbg(apply_twice(|x| x + 3, 10))
  add5 = adder(5)
  dbg(add5(1))
  dbg(apply_twice(add5, 0))
  ()
}
```

```console
$ emela run
16
6
10
```

`adder` は関数を返します。返された関数は、`adder` が終了した後でも `adder` のパラメータ `n` を使っています。無名関数は自分が使う変数を*キャプチャ*するのです。変数は決して変化しないため、キャプチャされた変数は関数が作られた時点の値を保持し続けます。

```emel
fn main() {
  n = 1
  f = || n
  n = 2
  dbg(f())
  dbg(n)
  ()
}
```

```console
$ emela run
1
2
```

2 つ目の `n = 2` は新しい束縛です（第 2 章）。`f` は最初の束縛を保持したままです。

関数値には、`fn` で宣言された関数とは異なるルールがいくつかあります。

- 関数値にはパラメータ名がないため、位置引数でのみ呼び出します。`add5(x: 1)` はコンパイルできません。型 `fn(Int) -> Int` にも名前は含まれません。
- 名前に束縛された無名関数は自分自身を呼び出せません。その名前が可視になるのは束縛の後だからです。自分自身を呼び出す関数は、トップレベルまたはローカル（後述）で `fn` を使って宣言します。
- 関数は比較も表示もできません。関数型は `Eq` も `Show` も持ちません。

### エラーとエフェクトは通り抜ける

関数型には、`fails` や `uses` でその関数が持ち得るエラーやエフェクトも書けます（第 5 章、第 6 章）。`List.map` の `f: fn(A) -> B` のようにパラメータの関数型でそれらを省略すると、任意のエラーやエフェクトを持つ関数を受け入れ、それらはそのまま受け取り側の呼び出しのエラーやエフェクトになります。したがって、失敗し得る関数を渡した `List.map` は失敗し得る呼び出しになり、待機する関数を渡した `List.map` は待機する呼び出しになります。1 つの `List.map` ですべてを賄えるため、エフェクト付き関数向けの別バージョンは必要ありません。

## パイプ

複数段階の計算を通常の関数呼び出しで書くと、`List.fold(List.map(List.filter(orders, ...), ...), ...)` のように内側から外側へ読む形になります。パイプ `|>` を使うと、同じ手順を実行される順に書けます。

```emel
type Order(item: String, price: Int, paid: Bool)

fn main() {
  orders = [
    Order(item: "tea", price: 300, paid: True),
    Order(item: "cake", price: 450, paid: False),
    Order(item: "coffee", price: 350, paid: True),
  ]
  total = orders
    |> List.filter(|o| o.paid)
    |> List.map(|o| o.price)
    |> List.fold(from: 0, f: |sum, price| sum + price)
  dbg(total)
  unpaid = orders |> List.filter(|o| !o.paid) |> List.length match {
    0 -> "all paid"
    n -> "#{n} unpaid"
  }
  dbg(unpaid)
  ()
}
```

```console
$ emela run
650
"1 unpaid"
```

`x |> f(a)` は `f(x, a)` と同じです。左側の値が、右側の呼び出しの第 1 位置引数になります。右側が呼び出しでない場合、`|> List.length` のように `x |> f` は `f(x)` になります。標準ライブラリの関数はこの形で使えるように、操作対象となる値を第 1 パラメータに受け取ります。

- `|>` で始まる行は前の行の続きになるため（第 2 章）、各ステップを 1 行ずつ書けます。
- パイプは他の演算子よりも弱く結合し、`match` はさらに弱く結合します。`orders |> List.filter(...) |> List.length match { ... }` は連鎖全体の結果に対してマッチします。

## メソッド呼び出し

関数は、第 1 引数を前に書いてドットでつなぐ形でも呼び出せます。

```emel
type Money(cents: Int)

fn add(a: Money, b: Money) -> Money {
  Money(cents: a.cents + b.cents)
}

fn describe(m: Money) -> String {
  "#{m.cents} cents"
}

fn main() {
  price = Money(cents: 1250)
  tax = Money(cents: 100)
  dbg(price.add(tax).describe())
  dbg(describe(add(price, tax)))
  dbg(price |> add(tax) |> describe)
  dbg([3, 1, 2].length())
  ()
}
```

```console
$ emela run
"1350 cents"
"1350 cents"
"1350 cents"
3
```

`price.add(tax)` は `add(price, tax)` と同じ呼び出しです。メソッド呼び出し `x.f(a)` は、`x` の型によって決まる次の 3 か所から `f` を探します（`[type.rules]`）。

1. その型が持つ `f` という名前のフィールド（関数を保持している場合）。
2. その型を定義しているモジュール内の `f` という名前の関数で、第 1 パラメータがその型であるもの。
3. その型が実装しているトレイトの関数 `f`（第 9 章）。

`[3, 1, 2].length()` が動くのは 2 番目のルールによるものです。`List.length` は `List` を定義する `List` モジュールにあり、第 1 パラメータにリストを受け取ります。別のモジュールにある関数は、どのようにインポートしていてもこの方法では見つかりません。

パイプとメソッド呼び出しは役割が重なる部分があります。メソッド呼び出しはモジュール名を書かずにその型に属する関数だけを見つけ、パイプは任意の関数を名前付きで呼び出せます。括弧のない `price.add` は関数値になりません。`price` を固定した `add` を渡したい場合は `|other| add(price, other)` と書きます。

## ローカル関数

トップレベルと同じように、ブロックの中でも `fn` で関数を宣言できます。ローカル関数はその宣言からブロックの終わりまで可視であり、宣言された場所で見えている変数を使えます。

```emel
fn count_down(from: Int) -> List[Int] {
  fn go(n: Int, acc: List[Int]) -> List[Int] {
    if n > from { acc } else { go(n + 1, [n, ..acc]) }
  }
  go(1, [])
}

fn main() {
  dbg(count_down(5))
  ()
}
```

```console
$ emela run
[5, 4, 3, 2, 1]
```

`go` は `count_down` のパラメータ `from` を使い、さらに自分自身を呼び出しています。`[n, ..acc]` は `acc` の要素の先頭に `n` を付けたリストです。`go` のように書いた関数が何度でも安全に繰り返せる理由は第 4 章で説明します。

ローカル関数はトップレベルの関数と同じルールに従います。パラメータの型は明記し、戻り値の型・エラー・エフェクトは推論できます。さらに次の制限があります。

- 独自の型パラメータは持てません。外側の関数の型パラメータは使えます。
- ブロックの最後の文にはできません。その後ろから呼び出すコードが存在しないためです。
- 2 つのローカル関数が互いに呼び合うことはできません。それぞれ自分の宣言以降でしか可視にならないためです。
- メソッド呼び出しでは見つかりません。

## まとめ

- 呼び出しなしの関数名、コンストラクタ、または `|params| body` が関数値になります。
- 関数型は `fn(A) -> B` と書きます。関数値は位置引数で呼び出し、比較も表示もできません。
- 無名関数は自分が使う変数を、作られた時点の値でキャプチャします。
- `List.map` などに渡した関数は、そのエラーとエフェクトを呼び出し側へそのまま伝えます。
- `x |> f(a)` は `f(x, a)` です。`x.f(a)` は `x` の型のフィールド、その型を定義するモジュールの関数、およびその型のトレイトから `f` を探します。
- ローカル関数はブロック内で `fn` を使って宣言でき、自分自身を呼び出せます。

第 4 章ではループなしで繰り返しを書きます。再帰、`List.fold`、そして深い再帰を安全にする保証について学びます。
